# Plan usage routes Steps and pauses without failing the issue

This amends [ADR 0021](0021-a-command-may-run-its-security-review-on-another-harness.md), where only a **Security review** ran on another **Harness**, and [ADR 0029](0029-in-progress-marks-only-a-live-run.md) and [ADR 0030](0030-a-full-disk-is-the-hosts-failure-not-the-issues.md), adding subscription **Plan usage** exhaustion beside a full disk as a reason to release an issue's **Claim** with work on `origin` without `agent-failed`.

A factory **Command** whose Harness comes from the **User config** walks `[harness] routes` (and `[security] routes`, falling back through `[harness] routes` for **Security reviews** and **Security runs**) per session **Step** according to machine-local **Plan usage**: proactively when a route is in cooldown or at or above `max_utilization`—holding included **Plan windows** ahead of paid or credit balances unless `allow_credits = true`—and reactively when a session stops on structured provider Plan-usage evidence (never on bare HTTP 429 throttling or agent-writable text). Explicit CLI `harness`/`model` flags, Step `harness` pins, **Experiments** and **Scoring runs** stay pinned, and a cybersecurity safeguard refusal still never routes and still holds **Self-merge**. When a session stops at a Plan-usage limit mid-Step after doing work, thirdshift keeps local commits, discards uncommitted worktree edits (re-applying any pinned conflict merge, and switching `Implement` from fresh to continuation once commits or an open pull request exist), and starts the next route with no added quota-warning prompt text.

When every allowed route is unavailable, scheduled **Passes** skip without sleeping ([ADR 0009](0009-the-operating-system-schedules-thirdshift.md)), and a live Command ends as a **Paused Command** (`outcome = "paused"`), stopping queued sibling Spec **Tickets** while active ones finish or salvage. An issue's Claim is released without `agent-failed`, putting `ready-for-agent` back when the Claim took it off unless an account that is not a **Trusted account** edited the issue since its last `ready-for-agent` labelling (which leaves `needs-triage`) or the Run is a Security fix (which keeps `agent-failed`). A Paused Command whose Claim put `ready-for-agent` back sits in Done rather than **Needs you** and saves its **Run notification** without emailing when only unmerged runs are emailed, because a later **Pickup run** continues it once a Plan window resets.

## Considered Options

- **Keep uncommitted edits on mid-Step fallback and prepend a handoff note to the Session prompt.** Rejected without an Experiment: telling an agent that the prior session ran out of subscription allowance risks skewing its behaviour toward rushing or cutting corners.
- **Query Fleet peers' `/api/v1/plan-usage` during Pass and Step routing.** Rejected: `thirdshift plan-usage` and `/plan-usage` aggregate across the **Fleet** and `console report`, while routing stays strictly machine-local so cron Passes make no cross-machine HTTP calls and passive-only Harnesses (`claude`, `agy`, `grok`) learn shared-login exhaustion in ~1s on a `before_first_turn` rejection.
- **Sleep in-process like GitHub Quota wait, or label exhausted Runs `agent-failed`.** Rejected: **Plan windows** and monthly spend caps span hours to weeks ([ADR 0009](0009-the-operating-system-schedules-thirdshift.md)), and account exhaustion says nothing about the issue, so `agent-failed` would trip the **Failure limit** ([ADR 0030](0030-a-full-disk-is-the-hosts-failure-not-the-issues.md)).

## Consequences

- Every configured route's **Factory skills** are linked into the worktree so a Step that switches Harnesses finds its skills.
- The pull request and Run notification `Built with` line keeps its single primary tuple for Scoring compatibility ([ADR 0021](0021-a-command-may-run-its-security-review-on-another-harness.md)), while `.models.json`, the **Command record** and the Run notification's Session models list record every Step's actual Harness and Model.
- Only structured Harness wire-frame events and official non-billed CLI/RPC reads count as Plan-usage exhaustion, never agent-writable text, so an agent cannot forge a pause or Claim release ([ADR 0030](0030-a-full-disk-is-the-hosts-failure-not-the-issues.md)).

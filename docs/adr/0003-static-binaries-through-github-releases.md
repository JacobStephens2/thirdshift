# Static binaries through GitHub Releases, mirrored to crates.io

thirdshift ships as prebuilt binaries on GitHub Releases, built by `dist` from a `v<version>` tag: a statically linked `x86_64-unknown-linux-musl` binary and a native `aarch64-apple-darwin` one, with a curl installer that puts `thirdshift` in `~/.local/bin` and an updater built into the binary (`thirdshift update`). The same version is mirrored to crates.io. We chose this over publishing to crates.io alone for three reasons:

- **No Rust needed to install.** `cargo install` needs the Rust toolchain on every machine that runs thirdshift, and the one-line install command (in the README, and later on thirdshift.app) should need nothing beyond `claude`, `gh` and `git`. A curl installer served from GitHub Releases means users trust GitHub, not a personal server.
- **glibc on Rocky.** A binary linked against glibc on a current Ubuntu runner won't start on Rocky Linux 9, whose glibc is 2.34. A musl binary is statically linked, so one Linux build covers Rocky, Ubuntu and WSL2, whatever their glibc.
- **The crate name is permanent.** crates.io names are first come, first served, and a published crate is effectively permanent: versions can be yanked, but the name stays taken. Publishing a real, working crate claims `thirdshift` before someone else does, but crates.io is a mirror for Rust users, not the documented install path.

## Consequences

- Every native dependency must link statically under musl. HTTPS goes through rustls, never OpenSSL.
- Only the platforms with a build are supported: x86_64 Linux (including WSL2) and Apple Silicon macOS. ARM Linux, Intel macOS and native Windows have no binary.
- The release workflow is generated by `dist` from `dist-workspace.toml`, and must be regenerated, not edited, after a change there or a `dist` upgrade. Custom steps (the Rocky and WSL checks, the crates.io publish, the release notes) hang off `dist`'s job hooks so a regeneration keeps them.
- The release is only published after the musl binary's `thirdshift version` runs in a Rocky Linux 9 container and in WSL2 with Ubuntu 24.04. crates.io is published after the GitHub Release, so a failed check publishes nothing anywhere.
- crates.io's trusted publishing can only be set up on a crate that exists, so the first version is published by hand, and the publish job skips a version that is already on crates.io.
- `thirdshift update` only replaces a copy with the installer's receipt. A crates.io install or a build from source is updated with `cargo`, and `update` says so instead of touching it.

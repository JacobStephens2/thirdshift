# What thirdshift can learn from other open-source software factories

Research date: 2026-10-25.

**Question.** Which practices of these open-source software factories would thirdshift benefit from, which does it already have, and which conflict with its ADRs (#836)?

- **addyosmani/factory**, by Addy Osmani.
- **ProPR** (`integry/propr`).
- **Anneal** (`mosonlab/anneal`).
- **AI Software Factory** (`coleam00/ai-software-factory`), by Cole Medin, which runs on his Archon workflow engine.
- **Agentic Orchestrator** (`doordash-oss/agentic-orchestrator`), by DoorDash. It calls itself "Agentico".
- **pocock-agents** (`mcdays94/pocock-agents`), the one closest to Matt Pocock's skills.

This note builds on [warp-factories-and-alternatives.md](warp-factories-and-alternatives.md) (the "earlier survey"), which compared about 27 products, Gas Town among them. It also builds on [sandcastle-fit.md](sandcastle-fit.md), [openhands-fit.md](openhands-fit.md) and [software-factory-console-trends.md](software-factory-console-trends.md). None of those covered the six projects above. Those notes asked whether a product could replace thirdshift. This one asks only what is worth borrowing.

## TL;DR

- **None of the six does thirdshift's whole job.**
  - **Unattended, issue-driven, merging:** only Cole Medin's factory runs unattended from GitHub issues to a merged pull request.
  - **Unattended up to a pull request:** addyosmani/factory and ProPR open pull requests unattended, but leave merging to a human. ProPR auto-merges only labelled plan work.
  - **Unattended, but not from issues:** Anneal runs unattended chains from cards on its own board, not from GitHub issues.
  - **Supervised:** DoorDash's Agentic Orchestrator is human-supervised by default, with six approval checkpoints. pocock-agents is an interactive OpenCode session.
- **Five run on the user's own CLI logins, as thirdshift does.**
  - addyosmani/factory, ProPR, Anneal, Cole Medin's factory and DoorDash's orchestrator all drive the official `claude` and `codex` CLIs, or Claude cloud routines, with the user's own subscription.
  - pocock-agents doesn't say how it authenticates, and its smoke test uses an API key. (§1)
- **Where they agree, thirdshift mostly already agrees.**
  - **Isolation:** a worktree is the only boundary. Anneal and Archon both say so in their docs. Only ProPR adds a container. This is thirdshift's ADR 0013.
  - **Merging:** deterministic code performs the merge, at the exact reviewed head, after re-checking it. That holds in Anneal, Archon and ProPR, as in ADR 0004. In Anneal no model takes part at all. In Archon the reviewer model decides to merge and names the commit, and a script checks and executes that decision.
  - **Review:** one review round, then fix and stop. Anneal's ADR-0009 removed its review-fix loop for cost, and pocock-agents says "A second full review never comes back clean". This matches thirdshift's Standards-and-Spec review.
  - **Bounded repair:** every factory with a CI loop caps it. Anneal allows 2 CI recoveries per chain ([ADR-0012](https://github.com/mosonlab/anneal/blob/bfa821b066355dfd321d15e43162a9047cfa4091/docs/adr/0012-recover-terminal-ci-check-failures.md#L14-L58)); Archon allows 5 delivery rounds ([archon-deliver-block.yaml L1-L18](https://github.com/coleam00/Archon/blob/99be58cd8288400d7ab80f576da0efa597daa17c/.archon/workflows/sdlc/deliver/archon-deliver-block.yaml#L1-L18)) and 3 attempts.
  - **Telling failures apart:** DoorDash's verification executor separates inherited failures from flakes, which ADRs 0008 and 0010 already do for CI.
- **thirdshift is ahead on intake hygiene and recovery.** It filters issue text to Trusted accounts. It reserves an issue on origin before dispatch (ADR 0017). It reviews Foreign commits before a Self-merge. It re-runs Abandoned jobs (ADR 0020). It writes Session traces in OpenTelemetry's format (ADR 0019).
  - The others have gaps here. ProPR's `/fix` trusts any comment that carries its review marker, whoever wrote it. addyosmani/factory's handoff comment has no authorship check, and its claim branches can jam the queue for good.
- **Worth adopting, most valuable first.** (§4)
  1. **A review from another model family.** Anneal and DoorDash both make it the default. It is already open as #429, with the evidence in [multi-family-review.md](multi-family-review.md).
  2. **Protected paths that hold a Self-merge.** Archon, ProPR and addyosmani/factory all refuse to self-merge a change to the factory's own policy, CI or charter. In Archon's case, "a reviewed delivery once rewrote `engineering.md` and merged". thirdshift has no such rule. This is a new suggestion.
  3. **Sessions that start without the user's personal agent config.** Anneal passes `--setting-sources project,local`, and DoorDash runs its reviewer in `--safe-mode`. ADR 0013 records that `~/.claude/` instructions reach thirdshift's Claude, Grok and Muse sessions but not the others. This is a new suggestion.
  4. **A mechanical check that a new test fails without the fix.** This is addyosmani/factory's `prove-test.sh`, minus its open bug that counts any non-zero exit as proof. It is a new suggestion.
  5. **A weekly check for drift from upstream skills,** as pocock-agents runs. It belongs under #321.
  6. **Re-running a Ticket run whose process was killed, once.** ProPR and Anneal both do this. It belongs under #710.
  7. **Pausing Ticket runs on subscription limits, then waking.** ProPR and Archon both do this. thirdshift already does it for Experiments and the Scoring run. It belongs under #583, #584 and #969.
  8. **A retro that proposes and never edits.** addyosmani/factory has `/factory-tune` and pocock-agents uses `retro`. It belongs under #322.
  9. **A Continuation that reads the pull request's unresolved review threads.** DoorDash runs this as a child feature. It is a new suggestion.
- **What conflicts with thirdshift's ADRs.**
  - **ADR 0009 (no daemon):** ProPR, Anneal and Archon all run a long-lived daemon or engine.
  - **ADR 0009 (one unattended run per repository on a machine):** Anneal's "parallel by default" breaks this. More than one is already open as #279.
  - **ADR 0013 (sessions run fully trusted, with no approvals):** DoorDash's mediated permission prompts conflict. So does a per-command deny list like pocock-agents'. DoorDash's approval checkpoints between phases don't conflict with it: they sit between sessions, which #696 already asks about.
  - **ADR 0004 (thirdshift merges, not GitHub):** ProPR's use of GitHub auto-merge conflicts. So does addyosmani/factory's rule that merging is never automated, on any tier. ADR 0004 agrees that no agent should merge from inside a session. But a never-automated rule would also remove the Self-merge, and with it ADR 0006's Spec branch.
  - **Worth reopening:** one conflict, ProPR's rule that only deterministic code commits and pushes while the agent gets a read-only token. It contradicts ADR 0013's premise that sessions push. It is still the most worked-out answer seen to the credential questions in #691 and #637. It has gaps of its own: orchestrated goals keep write tokens, and agent tokens can read every repository the GitHub App can see. (§3, §5)

## 2. Practice by practice

Each table lists a project's distinctive practices with the source and thirdshift's mark. Practices that several projects share are marked once, in the first table they appear in, and later tables refer back.

### 2.1 addyosmani/factory

A reference operating model: Markdown policy, skills and Bash scripts that Claude routines run. Most of its behaviour is instructions to the model. Its deterministic pieces are `gates.sh`, `prove-test.sh`, `block-merge.sh` and `doctor.sh`. One outside review found several defects, which the author's fix pull request is still open on ([issue #3](https://github.com/addyosmani/factory/issues/3)).

## 3. Patterns across the six

**Where the field agrees with thirdshift.**

- **The user's own CLI login.** Five of the six drive the official CLIs under the user's own subscription. That is route (a) in the earlier survey's §2, the plainest case under both vendors' terms.
- **A worktree, not a sandbox.** Anneal ([security.md](https://github.com/mosonlab/anneal/blob/bfa821b066355dfd321d15e43162a9047cfa4091/docs/release/security.md#L100-L117)) and Archon ([worktrees.md](https://github.com/coleam00/Archon/blob/63a5247f1bd1a51024f1f5d4e06be0a9a732760c/packages/docs-web/src/content/docs/guides/worktrees.md#L12-L14)) both state it in their docs. Only ProPR adds a container.
- **Deterministic code performs the merge.** Anneal, Archon and thirdshift all merge from deterministic code, at an exact head, after re-checking the base. In Anneal no model takes part. In Archon the reviewer model still decides to merge, and the `land` script refuses when the evidence doesn't hold. Archon added that gate after measuring that its reviewer "had sent back 0 of 37 pull requests" ([DECISIONS L47-L49](https://github.com/coleam00/ai-software-factory/blob/f81b06ce0417ed981d0411afce11e5263b0d2d7b/DECISIONS.md#L47-L49)).
- **One review round.** Anneal's ADR-0009 and pocock-agents both stop after one review and one fix round. ProPR's Ultrafix and DoorDash's Final Review loop ([final_review_loop.go L15-L25](https://github.com/doordash-oss/agentic-orchestrator/blob/51120679ff5cfdad563e5202dff479dd30c8e291/internal/agent/final_review_loop.go#L15-L25)) are the exceptions, and both are bounded.
- **Bounded repairs.** Every factory with a fix loop caps it, and most also stop early on no progress.

**Where thirdshift is ahead.**

- **Intake hygiene.** It filters issue text to Trusted accounts and re-checks for edits by others before each session. ProPR's `/fix` and addyosmani/factory's handoff comment both trust text from anyone.
- **Claim races.** ADR 0017's reservation is atomic, released by its owner, and needs no database. addyosmani/factory's claim branches are never deleted. Archon's comment claims rely on a 5-second wait.
- **CI semantics.** Inherited failures, Abandoned jobs and the Check re-run all read CI facts, never log text. Anneal and Archon re-run once for flakes. Only DoorDash classifies against the base, and only for its own verification commands.
- **Foreign commits.** No other factory reviews commits that land on its branch from elsewhere before merging them.
- **Security.** A Security run: a private Security audit, then reproduction and, when allowed, fixes (ADR 0015). The others have at most a dependency audit (addyosmani/factory's `gates.sh deep`) or a security critic (DoorDash).

**Where thirdshift is behind.**

- **Independence of review.** Two of the six default to another vendor's model for review. thirdshift reviews on the authoring Model.
- **Guarding the factory's own rules.** Three of the six refuse to self-merge changes to their policy or CI files.
- **Clean sessions.** Anneal and DoorDash keep the operator's personal agent config out of sessions.
- **Subscription limits for Ticket runs.** ProPR and Archon park work when a plan limit is hit, and resume it on the reset. thirdshift does this for Experiments and the Scoring run. A Ticket run that hits a limit before changing anything only releases its Claim for a later pass.

## 4. Suggested follow-ups

These are suggestions for the Day shift, not filed issues. Where an open issue already covers one, it is named.

1. **Another model family for the Standards and Spec review** (#429). Anneal runs a GPT and an Opus reviewer in parallel, each over the same pinned base and head. DoorDash defaults review to Codex while Claude implements. [multi-family-review.md](multi-family-review.md) gathers the evidence. ADR 0021 already lets one session, the Security review, run on another Harness, so the plumbing for a per-session Harness exists.
2. **Protected paths that hold a Self-merge** (new). Archon, ProPR and addyosmani/factory all refuse to self-merge a change to their own policy files. Archon's reason was a reviewed delivery that "rewrote `engineering.md` and merged".
   - **The thirdshift version:** a Ticket run asked to merge, whose diff touches the repository's CI workflows, `AGENTS.md`/`CLAUDE.md`, `.claude/` or `.agents/`, or a User-config list of paths, leaves its pull request ready for review instead of merging. This works like a Policy refusal.
   - **Where it is checked:** against the diff GitHub reports, as ProPR does, not the worktree.
   - **Interaction:** it would interact with #966's per-command Self-merge settings.
3. **Factory sessions that don't load the user's personal agent config** (new).
   - **Today:** ADR 0013's consequences note that `~/.claude/` instructions reach Claude, Grok and Muse sessions but not Codex, agy or OpenCode. So a Ticket run's behaviour depends on the machine and the Harness.
   - **The fix:** Anneal passes Claude `--setting-sources project,local` and `--strict-mcp-config`; DoorDash's reviewer uses `--safe-mode`. thirdshift could pass the equivalent to every Harness that has one.
   - **Open questions:** whether users rely on their personal instructions reaching factory sessions, and what each other CLI offers. Both need checking before deciding.
4. **A mechanical red-without-the-fix check for new tests** (new). For a Ticket run that adds a test, thirdshift reverse-applies the non-test hunks in a throwaway worktree, runs that test, and records whether it fails. That is addyosmani/factory's `prove-test.sh`.
   - **Lesson from its open bug:** count only a test failure, not any non-zero exit.
   - **What it gives:** a factory-owned fact for the pull request body and the Run metrics, not a gate. Many fixes legitimately add no test.
   - **Overlap:** it overlaps with the Security run's proof-of-concept reproduction and the Security review's failing tests, and with #726's sandbox runner for executing such tests.
5. **A weekly check for upstream skill drift** (#321). pocock-agents runs a weekly Action that fails when a skill it names is removed upstream. thirdshift's Factory skills are adapted copies, so the useful signal is upstream changing a skill they were adapted from: a diff to review, not a failure.
6. **One re-run of a Ticket run whose process was killed** (#710). ProPR gives an orphaned run exactly one replacement, continuing the pushed branch, and records lineage so the cap survives restarts. Anneal retries a lost lease while the run budget lasts. Today a killed Ticket run leaves its issue `in-progress` until a person acts. Any re-run must respect the Pickup reservation's owner rule (ADR 0017).
7. **Pausing Ticket runs on subscription limits, then waking** (#583, #584, #969). thirdshift already reads plan limits from the Harness's events, and an Experiment or Scoring run stops at a plan-limit warning and resumes when run again ([src/session/limits.rs](../../src/session/limits.rs#L14-L16)). ProPR defers scheduled work above 90% of the plan's usage, and parks a run that hits a limit until it resets. Archon puts such a run in a durable wait, and its timer wakes it. A Pass could skip with exit 0 while the Harness reports a limit, which fits ADR 0009 better than a waiting process.
8. **A retro that proposes and never edits** (#322). Both addyosmani/factory's `/factory-tune` and upstream `retro`, as pocock-agents uses it, gather evidence and propose changes, leaving a human to apply them. In thirdshift that could read Run metrics and Unaddressed findings across recent Ticket runs, and file one `needs-triage` issue.
9. **Repository holdouts and a black-box app check** (input to #883, #1092). Cole Medin's factory checks the running app before reading the diff, against scenarios the builders can't see. It found builders reading the judges until a hook fenced them off. That fence exists only for Claude Code. Any thirdshift version would need it on every Harness first.
10. **A Continuation that reads the pull request's unresolved review threads** (new). DoorDash's review-feedback child feature fetches unresolved review comments, answers each and resolves the threads. A Day shift reviewer who comments on a thirdshift pull request and hands the issue back gets a Continuation whose Session prompt doesn't mention those comments ([prompts/continuation-pr.md](../../prompts/continuation-pr.md)). Like issue comments, the threads would need filtering to Trusted accounts first.

## 6. Uncertainties

- **Maturity.** Five of the six were created in 2026, and five of the six are mostly one author's work. ProPR has the longest record: daily use since May 2025 ([README L363-L373](https://github.com/integry/propr/blob/5559dea9e53656a42ac8ceec2695d89ae986001d/README.md#L363-L373)) and 1,600 merged pull requests. addyosmani/factory has not changed since 2026-08-21. Anneal has not been pushed since 2026-09-26.
- **Docs that disagree with code.** Anneal's README promises two blind reviews, but one is optional and ADR-0009 removed it as a gate. Anneal's ADR-0007 says "repair once per kind", but its code allows 3. DoorDash's docs give a different "inquireness" default from its code. Where they differ, this note follows the code.
- **Cole Medin's factory depends on an unmerged Archon branch,** and plans to retire its own wrapper into Archon triggers ([#55](https://github.com/coleam00/ai-software-factory/issues/55)). Its practices may move.
- **What each other Harness offers in place of `--setting-sources`** (§4.3) was not checked.

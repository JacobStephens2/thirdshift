Your issues go to press overnight.

The humans are the day shift: you talk the idea through, write the spec and cut it into tickets. Coding agents work the third shift: give thirdshift a GitHub issue URL and it implements the issue, reviews its own work and delivers a pull request ready for review, or merges it when asked. Start a Run whenever you like, or let your operating system start passes on a schedule.

How thirdshift works: an engineer's guide from issue to pull request, through Worktrees, agent review and Delivery. Architecture draws what runs where and who does each step. Documentation covers installation, commands and configuration. Videos explain it in a few minutes.

How a Run works

One issue in, one pull request out.

A Run feeds one issue through four units and delivers a pull request that is ready for review, or merged in a Merge run. Units 2 and 3 are one agent session in the Harness you choose. Under each unit are lines thirdshift printed on stderr during a real Run, overnight on 12 October 2026. A scheduled Pickup run took issue #663 at 00:21, and its Merge run merged pull request #665 at 01:22. That pull request refreshed the floor plan further down this page. 4 · K · Finish

An optional Security review checks the change first. Then thirdshift pushes, checks the pull request, merges the Base branch in and watches CI. A merge conflict or failing CI starts a Repair, at most 5. A Resume can happen in any session and isn't a Repair. The Run ends once the pull request is open, ready, mergeable and passing CI. A Merge run, from thirdshift merge <Issue URL> or the User config, then merges it. Here the Security review found nothing, main moved during CI and was merged in again, and no Repair was needed.

    Misprint: a Failed run

    A Run that ends, including by interruption, without an open pull request from its Issue branch that targets the Base branch, is mergeable, and has passing CI is a Failed run. Nothing is lost: its work, uncommitted changes included, is committed and pushed to the Issue branch (or, if the push fails, its worktree and local Issue branch are kept), and its open pull request, if any, goes back to draft. Run the same command again to continue it.

    Illustrative. These are the last stderr lines of a standalone Run whose CI is still failing after 5 Repairs, with its work pushed and no notification requested. The Recovery command assumes Claude Code, no Model or Effort override, no Security review or fix, and no Base fix choice. The lines and their order come from the ending renderer and Recovery code, not a real Run.

    Delivery pile

    What comes off the press

    Ready for review

    An open pull request from the Issue branch to the Base branch. It is mergeable, its CI passes, and it has been reviewed against your repository's documented coding standards and against the issue. Otherwise thirdshift doesn't call it ready.

    Unaddressed findings

    Every Standards finding and Spec finding the agent chose not to fix is listed as an Unaddressed finding in the pull request body, with the code, plan decision, ADR or focused run that refutes it. A decision left to the Day shift links a needs-triage issue.

    Failed runs keep their work

    A Failed run still pushes its work, so nothing is lost (if the push fails, it keeps the worktree instead), and its pull request goes back to draft. Run the same command again to continue it.

    Plan view · the press hall

    The factory grows

    One Run is the first primitive: one Issue URL in, one pull request out. The factory now builds with six workflows. Every line on this floor is installed; follow it to the documentation.

    A Merge run merges its own reviewed, green pull request when you ask. A Spec run works through Tickets in dependency order, up to three at once by default. They merge into a Spec branch, then one Spec PR gets reviewed against the whole Spec.

    An Architect run looks for architecture improvements and builds its top Strong plan. Without a Strong recommendation, it leaves an Architect idea for the Day shift. Use --plan-only to publish a plan and stop.

    A Pickup run takes the lowest-numbered Ready issue, after it has settled and while the repository is below its Claim limit. Failed work stays with the Day shift until you hand it back by applying ready-for-agent again.

    A Security run audits the Base branch and records findings privately. It is report-only by default. With security-fix, it can fix a reproduced finding through a Run or Spec run. An optional Security review checks each Run's change, including Tickets and the Spec PR, and holds Self-merge if introduced findings remain unaddressed or the review is incomplete. Its Harness is checked before work; an unavailable review Harness falls back to the default Harness, with one fallback also allowed for a Harness error before its first turn.

    Start passes with thirdshift architect base main, thirdshift pickup base main or thirdshift secure base main. Your operating system schedules them. Frequent Architect runs are Weeding; scheduled Security runs with fixing allowed are Fencing. Both yield to work the Day shift shaped, and pause when a decision needs you.

    The Console opens on this machine's Inbox: Commands grouped by what needs you, with their stages and logs. A signed-in account can Stop or Requeue a live Command, just as from the CLI.

    Experiments compare a Candidate with a Baseline on private Eval suites. thirdshift experiment <candidate> builds both Arms and runs interleaved Trials with two workers, a fixed Bar and resume after interruption or a plan-limit warning. Trials and Graders run in bwrap sandboxes. Code Graders score mechanical checks offline from report packets and the prepared repository, then fresh model Graders score written criteria from blind packets with provider-only access. Graders cannot read raw Trial logs, Arm mappings or the Experiment’s other files. Results show the Verdict, wrong findings, borderline marks, paired intervals, each Arm's minutes, tokens by Model, reported cost and Void causes. Trials and Graders join the Command's Trace. Void Trials retry fresh up to twice; an exhausted task drops out of both Arms. More than a tenth dropped makes the Verdict inconclusive.

    Experiments, including release Experiments, report approved Eval tasks missing Trial inputs before building either Arm. Spec review Trials keep the production prompt and grade only the reports; their sandbox blocks gh calls and provides no PR service.

    The Console's Experiments pages group saved Experiments into Running, Needs you and Done. Each Experiment updates live with its Trial grid, Verdict intervals, Arm comparison and Bar. Open a Trial's Peek for its Scores, reasons and session evidence; copy recheck commands to run in the CLI.

    Each Trial and each Grader has its own memory cap. A Trial its cap kills is void; repeated cap kills are reported for its Arm. The User config sets the caps, with defaults of 1 GiB for throttling, 2 GiB for killing and 1 GiB of swap.

    The Verdict waits for your rechecks of borderline and decisive Scores. thirdshift experiments <id> --json lists those waiting; thirdshift recheck <id> <trial> pass --reason '…' records your decision beside the Grader's Score and keeps its history.

    thirdshift experiment --release <commit> compares touched suites with the last release tag. The release script waits for rechecks before pushing and asks whether to release on a fail or inconclusive Verdict. Reruns reuse the Experiment, including before opening a pushed branch’s PR. No touched suite or a last release with no Trial flag carries on with a note. Release checks.

    Before you run it

    Requirements and platforms

    Requirements

    • Your chosen Harness, installed and authenticated: claude (Claude Code, the default), codex (Codex CLI), agy (Antigravity CLI), grok (Grok Build), muse (Muse Code) or opencode (OpenCode, with a configured Model provider).
    • gh (GitHub CLI), logged in.
    • Node.js on PATH for Security runs, whose report validators use it.
    • git with a global user.name and user.email, and credentials that can push to the repository.

    Platforms

    • Rocky Linux 9.8 and later, x86_64.
    • Ubuntu 24.04.3 and later, x86_64.
    • WSL2, latest release, with Ubuntu 24.04 or later, x86_64. Keep your repositories on the Linux filesystem (e.g. ~/repos), not under /mnt/c. WSL1 is not supported.
    • macOS Tahoe 26.5.2 and later, Apple Silicon.

    Choose the Harness, Model and Effort with thirdshift setup or per command. See Harness configuration and supported platforms.

    Colophon

    Third shift

    My dad, Mark Stephens, was a pressman at Tursack Printing, the print shop Robert Tursack Sr. founded in Philadelphia in 1959. My dad worked third shift at the Morgantown, Pennsylvania plant, keeping the big four-color presses running through the night. Sometimes I got to visit, and I always wondered whether I'd end up in printing myself. The lineage carries on. Bob Tursack went on to found Brilliant Graphics in Exton, where my mom, Melodee, did graphic design with him until he sold the company to Royercomm Prism in 2026. This is as close as I am to printing right now.

    The printing press made copying words cheap. Agents are doing that for code. thirdshift is named for my dad's shift: the machines can run overnight, and I need something to keep them running.

    - Jacob Stephens

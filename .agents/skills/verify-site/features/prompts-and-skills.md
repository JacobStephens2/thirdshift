# Prompts and skills

The Prompts and skills page (`/prompts/`) displays the generated command line, Session prompts, embedded Factory skills, and license notices inside collapsible sections.

## Sub-features

- `prompts-top-folds` toggles `How each session starts`, `What a Ticket run tells the agent`, `Factory skills`, and `Licence`.
- `prompts-skill-sheets` opens a skill fold revealing its `SKILL.md` open by default while keeping supporting files folded.
- `prompts-deep-links` navigates directly to `#skill-thirdshift-verify-ui` or `#prompt-resume` and unfolds ancestors automatically.

## How to get to it (user POV)

- Follow `Prompts and skills` from `/` or open `$origin/prompts/`.
- Expand `Prompts`, `Factory skills`, or follow a deep-link fragment URL.

## Driving it with Playwright

Preconditions:

- `serve-site.cjs` is running on `$origin` and `Doctor` passed.

- **Confirm closed initial folds.** Open `${origin}/prompts/`. Zero `main > section > .wrap > details[open]` top-level sections are open.
- **Open a Factory skill.** Click `#skills-title`, then click `#skill-thirdshift-verify-ui-title` (or `#skill-thirdshift-code-review-title`). The skill's `SKILL.md` body becomes visible immediately while sibling supporting files remain folded.
- **Follow a deep-link fragment.** Navigate to `${origin}/prompts/#skill-thirdshift-pr` (or click `summary:has(#licence-title)` to open the Licence fold, then click a `#file-*` link inside its sibling `<p class="lede">`, `details:has(#licence-title) > p.lede a[href^="#file-"]`). Containing `<details>` ancestors open and scroll the target into view.
- **Proof.** Capture `1440×900` `.png` of an opened Factory skill sheet and record a `.mp4` walkthrough expanding `Factory skills` -> `thirdshift-verify-ui` -> fragment reveal.

## Gotchas

- `site/prompts/index.html` is partially generated by `src/prompts_page.rs`; after editing `src/prompt.rs` or `skills/`, run `UPDATE_PROMPTS=1 cargo test prompts_page` before serving.
- Local servers omit `/commit.txt`, so `[data-commit]` keeps its fallback text while `fetch('/commit.txt')` logs one expected 404 console error; filter `m.location().url.endsWith('/commit.txt')` in Playwright console-error assertions so genuine broken resources still fail.
